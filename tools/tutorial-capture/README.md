# Tutorial capture tool

Takes **real screenshots** and records **short walkthrough videos** of a locally running P7 ERP
for the in-app **Help & Tutorials** module (`/app/tutorials`). It is a developer tool only — it is
not part of the frontend or backend build and nothing here is deployed.

```
tools/tutorial-capture/
├── capture.mjs               # signs in once, runs manifests, writes images/videos
├── check-assets.ts           # validates tutorial content (missing images, bad article links)
├── dump-sidebar-routes.ts    # builds manifests/_sidebar.json from the sidebar config
├── manifests/
│   ├── _sidebar.json         # one screenshot per sidebar link (generated)
│   └── <section>.json        # extra screenshots + videos per tutorial section
└── package.json              # only dependency: playwright-core (uses installed Edge)
```

Output goes to `frontend/public/tutorials/`:

| Folder | Content |
|---|---|
| `screens/<name>.jpg` | Screenshots (1440×900, JPEG) |
| `videos/<name>.webm` | Walkthrough videos (1280×800) |
| `videos/<name>-poster.jpg` | First frame shown before a video plays |
| `diagrams/<section>/*.svg` | Hand-made diagrams (not generated by this tool) |

## One-time setup (local Docker)

1. Start the stack: `docker compose up -d` (frontend on `http://localhost:5173`).
2. Create the dedicated capture user (local only — the script refuses to run in production):

   ```powershell
   docker compose exec -e TUTORIAL_CAPTURE_PASSWORD=<password> backend python scripts/seed_tutorial_capture_user.py --company-code LAKH806201
   ```

   A separate user is needed because the ERP allows **one session per user**: capturing with
   your own account would keep signing you out of your browser.
3. Install the tool: `cd tools/tutorial-capture; npm install`
   (behind a TLS-inspecting proxy: `$env:NODE_OPTIONS="--use-system-ca"` first).
4. Install the small ffmpeg build Playwright needs for video recording (screenshots work without it):
   `node node_modules/playwright-core/cli.js install ffmpeg`

5. **Mask real people (required — the repo is public).** Copy `redact.example.json` to
   `redact.local.json` (git-ignored) and list every real name, username and email that can appear on
   screen, mapped to a placeholder. The tool replaces them in the page before every screenshot and
   throughout videos, and refuses to save a capture where one is still visible.

## Running

```powershell
cd tools/tutorial-capture
$env:CAPTURE_PASSWORD = "<password>"
node capture.mjs --manifest=inventory --only=shots   # screenshots of one manifest
node capture.mjs --manifest=inventory --only=videos  # videos of one manifest
node capture.mjs --name=inv-po-form                  # one entry (or several: --name=a,b,c)
node capture.mjs --skip-existing                     # keep files that already exist
npm run routes                                       # regenerate manifests/_sidebar.json
npm run check                                        # validate tutorial content (+ list unused files)
node capture.mjs --referenced-only                   # refresh only files that articles use
npm run check -- --delete-unused                     # delete screenshots/videos no article uses
.\compress-videos.ps1                                # shrink new videos (~85% smaller) via Docker ffmpeg
```

Raw recordings are large (about 6 MB per minute). Always run `compress-videos.ps1` after recording,
before committing; it re-encodes to VP9 with an ffmpeg Docker image and keeps text readable.

Only one capture runs at a time (a `.capture.lock` file makes later runs wait), because every run
signs in again. Results are written to `capture-report.json` (`ok` / `warning` / `failed`).

## Phone-size audit

`node mobile-audit.mjs` opens the routes in `mobile-audit-routes.json` at 360px and 390px with the browser
in dark mode, and reports sideways overflow, controls cut off at the right edge, dark mode, print problems
and small tap targets. Output goes to `.mobile-audit/` (git-ignored). Severity rules and the latest result:
`docs/MOBILE_RESPONSIVE_AUDIT.md`.

## Manifest format

```json
{
  "screenshots": [
    {
      "name": "inv-po-new-form",
      "route": "/app/inventory/purchase-orders/new",
      "waitMs": 2000,
      "fullPage": false,
      "clipSelector": "form",
      "actions": [{ "click": "text=Add line" }]
    }
  ],
  "videos": [
    {
      "name": "inv-create-po",
      "title": "Create a purchase order",
      "steps": [
        { "goto": "/app/inventory/purchase-orders" },
        { "caption": "Open Purchase Orders from Inventory in the sidebar" },
        { "click": "role=button[name=/New purchase order/i]" },
        { "fill": ["input[name=reference]", "PO-DEMO"] },
        { "caption": "Fill the header, add lines, then click Save" }
      ]
    }
  ]
}
```

**Actions** (used in `actions` and `steps`): `goto`, `caption` (text banner at the bottom of a
video; `ms` = how long), `click`, `hover`, `fill` `[selector, value]`, `select` `[selector, value]`,
`press` (key), `scroll` (pixels), `waitFor` (selector), `waitMs`. Selectors are
[Playwright selectors](https://playwright.dev/docs/locators) such as `text=Save`,
`role=button[name="New"]`, or CSS.

In videos, a red dot shows the mouse and the clicked element is outlined before each click.

**Rules for videos:** never click final **Save / Submit / Approve / Post / Delete** — stop at a
filled form and say "Click Save to finish" in a caption, so recordings do not change data.
